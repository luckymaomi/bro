# 飞行部面试通报更新

## 报装

```
飞行部面试通报更新
1. 场景：面试群有新通报，要把结果补进《飞行部面试通报》，并筛出可申请报务检查的人
2. 能干：认水位 → 抽未入库 → Markdown 预检（含类型预判）→ 主人确认后写入 → 出申请检查 Excel
3. 口径：表日期=面试日；去重键=姓名+员工号+面试类型+日期；备注本技能不碰
4. 申请检查：仅本轮新入库且结论=通过的「北美报务→EAMA」「欧洲报务→EEUO」；列含中文名+代码
5. 主人先交：通报表路径 + 聊天材料（ehomebot 导出／粘贴／摘录文件三选一）
6. 节奏：缺料先列「还缺什么」；有导出可自行判断缺口；预检后必须停审；备注不改
7. 铁律：预检 Markdown 语义判断后手写，禁止脚本正则直出拟新增表
```

## 综述

启动说法包括「更新面试通报」「面试群入库」「飞行部面试通报更新」「刷一下面试表」。

```
主人，小弟到了。飞行部面试通报更新，已就位。
开场先对齐你要交的料：飞行部面试通报表路径、聊天材料（ehomebot 导出／粘贴／摘录）；缺哪件报哪件。
齐了先报水位与未入库项；预检 Markdown 给你审，点头再写表。
申请检查只盯北美报务（EAMA）和欧洲报务（EEUO），且本轮新入库、结论通过才出表；备注不改。
```

材料未齐只问缺项、不臆造；已齐则直接执行对应阶段。

## 主人需提供（开场必对齐）

加载本 Skill 或开干前，先按下面清单对料；缺一项就点名要。完全不懂业务也能照清单交。

### 一、每轮必交

1. **通报表**（`飞行部面试通报.xlsx` 或主人指定同用途表）
   1. 用途：认水位、去重、追加「全部记录」
   2. 至少含列：姓名、员工号、面试类型、日期、结论、面试员、评语、备注
   3. 常见落点：桌面或仓根；路径须点明或确认「用仓根那份」
2. **聊天材料**（三选一或组合，至少一种）
   1. **ehomebot 历史导出**（`summary.json` + `群聊/*.ndjson`，会话名含「面试」优先）——可自行判断缺口，最省事
   2. 对话里**粘贴**的复制聊天
   3. txt／md／docx **摘录文件**路径

### 二、口头指定（可不另交文件）

1. **日期窗**：指定了日期或区间 → 只处理该窗；有 ehomebot 且未指定 → 以表内最大面试日为水位，只扫晚于水位的；只有糊成一团的复制文本且未指定 → **必须问**从哪条开始
2. **是否写入**：默认先 Markdown 预检停审；明确「写入／入库」才改通报表
3. **花名册／实力表**（补员工号用）：通报表 Sheet2 或已有记录不够时再要；仓根有当轮实力表且主人说可用则沿用

### 三、材料从哪来（小白指路）

1. **通报表**：飞行部维护的《飞行部面试通报》业务表，不是飞行门户技术资料导出。
2. **ehomebot 导出**：用 ehomebot 从面试相关群聊导出的历史包；没有导出时改粘贴或丢摘录文件。
3. **本任务不需要**技术等级／运行资格导出；报务申请表由本轮入库通过结果生成，不必事先另交空表。

### 四、开场缺料时报法（示例）

```
还缺：1. 飞行部面试通报表路径  2. 聊天材料（ehomebot 导出 或 粘贴 或 摘录文件）  3. 日期窗不说则：有导出按表内水位；纯粘贴须你说从哪条开始
已有：无（或列出已有路径）。齐了先报水位与预检，不写表。
```

## 输入（细则）

1. **通报表**（默认主人指定；常见桌面或仓根 `飞行部面试通报.xlsx`）：工作表「全部记录」，列至少含：姓名、员工号、面试类型、日期、结论、面试员、评语、备注。
2. **聊天材料**（三选一或组合）：
   1. ehomebot 历史导出（`summary.json` + `群聊/*.ndjson`，会话名含「面试」优先）——可自行判断缺口。
   2. 对话里粘贴的复制聊天。
   3. txt／md／docx 摘录文件。
3. **非导出输入**：先问清「起止怎么切、是否含发送人／时间、是否只贴了部分人」，确认后再抽，不臆造字段。
4. **日期窗**：
   1. 主人指定了日期或区间 → 只处理该窗。
   2. 未指定且有 ehomebot 导出 → **自行判断**：以表「全部记录」最大面试日期为水位，处理面试日（解析得出）**晚于水位**、且表内无同键的通报；并报告水位与未更新清单。
   3. 未指定且无导出、只有糊成一团的复制文本 → **必须问主人**日期窗或「从哪条开始」，不得瞎扫全历史冒充已对齐。

## 作战阶段

| 阶段 | 做什么 | 边界 |
| --- | --- | --- |
| **水位与缺口** | 读表；有导出则对照群长文／附件名；报最大面试日、已有条数、疑似未入库条数 | 不写表 |
| **预检** | 生成 Markdown：拟入库行（类型预判、待定、冲突、缺工号等） | 不写表；必须停等主人确认 |
| **写入** | 主人确认后备份再追加「全部记录」 | 不改旧行；不碰备注列 |
| **申请表** | 主人确认写入后，生成本轮申请检查 Excel | 仅本轮新入库＋通过＋北美／欧洲报务 |

任务阶段与授权遵循 AGENTS.md。

## 从聊天抽什么

1. **有效通报**：含面试结论语义的长文（通过／不通过／结论等）；一条可含多人 → **拆成多行**预检，禁止糊成一行。
2. **丢弃**：纯「辛苦」回执、加 WPS／联系人、排班安排、@ALL 通知、无结论的闲聊；只有附件无长文 → 进待审，**不编造评语**。
3. **字段**：
   1. 姓名：优先命中通报表 Sheet2／已有记录／当轮实力表花名册中的真名，禁止把「熟悉掌握」等短语当姓名；员工号文内优先，缺则花名册补，仍缺 → 待审。
   2. 面试类型：预判进表内类别。现行四类：**北美报务**、**欧洲报务**、**初次进入国际（航前面试）**、**初次进入美线**。群里「初次进入国际」「航前面试」「初次航前」等说法一律归并写入 **初次进入国际（航前面试）**，不要再写旧名「初次进入国际」。对不上 →「待定」等主人改。一检／转机型／转档等未入库类别默认待定，不擅自扩表枚举。
   3. 日期：优先文内面试日；文内没有可用消息日并在预检里标明「日期取消息日，请核」。
   4. 结论：通过／不通过（原文近义归一；吃不准待定）。
   5. 面试员：默认取发通报人；转发／代发吃不准则待定。
   6. 评语：用通报正文（可按人裁切）；不润色成另一套话。
4. **去重键**：姓名 + 员工号 + 面试类型 + 日期。表内已有 → 跳过；键冲突或同人同日疑似另一场 → 预检单列。
5. **备注**：本技能**永不写入、不改**「已申请检查」等备注。申请检查是后续人工／别流程；本篇只出申请名单表。

## 申请检查 Excel

1. **时机**：通报表写入已确认完成之后（可同一轮紧接着出）。
2. **纳入**：仅**本轮新入库**、结论=通过、面试类型为「北美报务」或「欧洲报务」。
3. **映射**：北美报务 → 北美报务检查 / EAMA；欧洲报务 → 欧洲报务检查 / EEUO。初入国际、初入美线等**不进**申请表。
4. **列**：姓名、员工号、报务类型（中文）、报务类型代码。
5. **命名**：`报务检查申请_姓名工号清单_截止YYYY-MM-DD.xlsx`（日期取本轮处理日或主人指定）；落仓库根或主人指定路径。

## 铁律：预检 Markdown 必须语义写，禁止脚本直出

1. **预检 Markdown 由小弟读聊天后语义判断再落盘**（姓名是否真是人名、一场几人、类型、结论、日期取文内还是消息日、评语怎么裁）。
2. **禁止**用脚本正则扫群后把「拟新增表」整表自动打印进 Markdown 交差。程序最多辅助：列水位、捞候选消息原文、查工号；**表意行必须人工语义过一遍再写**。
3. 演练／实办均同此铁律。写歪的自动表作废，重写预检。

## 预检 Markdown 最低内容

1. **只写一张表**（按面试日／消息日时间顺序），不要分段标题、不要说明废话，方便主人直接改表审核。
2. 列：日期、姓名、员工号、预判类型、结论、面试员、状态、评语摘要（可按主人当轮加减列，但默认这一套）。
3. 状态用短标签即可：可写入／待定-缺类型／待定-缺姓名／跳过已存在／丢弃 等。
4. 表内必须是语义判断后的真人真事；禁止脚本脏抽名入表。
5. 未确认不写通报表。

## 写入纪律

1. 先备份通报表，校验备份可读；失败则停。
2. 默认**追加**新行到「全部记录」；不覆盖旧行；不排序搅乱主人习惯除非主人要求。
3. 保留其它工作表（含 Sheet2）不动。
4. 写完报告：新增条数、跳过条数、待定未写条数、申请表路径（若已生成）。
5. 过程脚本与预检 md 落 `_tmp/` 或根目录说明路径；通报表与申请表交付件路径聊天报清。

## 与其它技能边界

1. 报务资格码周期／有无报务盘 → 「南货航飞行部潜规则」，本篇不管周期统计。
2. 资质录入通知拆解／门户录入动作 → 「机组门户系统录入指南」，本篇不出录入通知。
3. 本篇不登录门户、不代提检查申请，只维护通报台账与申请名单表。
