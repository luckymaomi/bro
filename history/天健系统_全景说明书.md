## 0. 一句话定锚

天健（`ifly.csair.com`）是南航飞行域的 **统一门户 + 多业务微前端 + 多 `*-app` 后端**。  
货航已经在逻辑模型里（公司／基地码 `CS`／`CSG`），靠 **菜单权限 + 数据权限** 裁可见范围；前端未见独立租户库开关。  
要「完全隔离」时，合理默认是 **同宗产品 + 分库／独立实例**，不是重开一套，也不是永久双轨镜像分叉。

## 1. 访问与鉴权（已彻底跑通）

### 1.1 网页链路

1. 业务：https://ifly.csair.com/ → 路由 `#/portal/index`  
2. 未登录 → IAM：`iam.csair.com`，`client_id=iFLY`  
3. OAuth `code` 回 `#/login` → `doLoginIam` → Cookie `IFLY_TOKEN`

### 1.2 HTTP 必带参数

| 参数 | 位置 | 备注 |
| --- | --- | --- |
| Cookie（含 IFLY_TOKEN） | Cookie | 仅 `document.cookie` 常不够 |
| **IFLY-TOKEN** | Header（横杠） | 缺则 401；与 Cookie JWT 同值 |
| RESOURCE-ID | Header | 常见 `bnVsbA==`（null） |
| Referer/Origin | Header | `https://ifly.csair.com/` |

取法：门户内 Network 选 `loginUserInfo` → Copy as cURL → 写入 `天健cookies.txt`。

### 1.3 本轮探针身份

员工号 295494／张峻哲；`orgunitBase=CSG`（货航）；部门＝货航飞行部训练管理室；岗位＝资质管理。  
角色含「值班员(重航和货航)」等。说明：**货航账号本来就能进这套天健**，不是外系统。

### 4.2 本号 API 烟测（有菜单 ≠ 有接口权）

| app | 烟测 | 含义 |
| --- | --- | --- |
| login / manage / os(options) / info(指引) | 业务 200 | 账号可用的底座 |
| qual / train-manage / school / label / fleet | 403 | 模块在系统里，本号未授权 |
| profile | 1010 | 接口在，无数据权 |
| irms unreadCount | 400 方法不对 | 要换 POST／参数，不是没有模块 |

结论：用全量菜单看「系统有没有」；用有权菜单 + 403／1010 看「货航这个号能不能干」。

## 5. 数据与组织模型（库怎么「逻辑」切）

拿不到 DDL，但逻辑已明：

1. 公司枚举：`CZ` 南航、`CS` 南货航、`OQ` 重航；基地／人事侧常见 `CSG`＝南货航。  
2. 用户身上：`orgunitBase`／`hrBase`／`flyBase`／`fleetGroup`／角色树。  
3. 权限两层：菜单／接口 403；记录级 1010。文案有「数据权限」「基地权限」「航校数据权限」。  
4. 前端无 `tenantId`／分库／sharding 产品开关。  
5. 部分业务文案区分来源：如作风「南航＝天健，货航／重航＝飞行门户」——历史路径差，不是「货航不在模型里」。

因此：现网是 **逻辑多公司的大一统库（或微服务多库但仍共享公司维）**，不是空白货航库。

## 6. 业务码习惯

| code | 含义 |
| --- | --- |
| 200 | 业务成功 |
| 400 | 常为 HTTP 方法错（看 msg） |
| 403 | 无接口／菜单权 |
| 1001 | 缺参数 |
| 1010 | 无数据权／无该记录权 |
| 500 | 服务端错 |

以 JSON `code` 为准，不要只看 HTTP 200。

## 7. 改造方案：怎样才「彻底合理」

### 7.1 选项

| 方案 | 做法 | 匹配度 |
| --- | --- | --- |
| A 同库强化权限／菜单裁剪 | 继续共库，CSG 数据权限收紧，关掉学员等菜单 | 贴现网；隔离弱 |
| B 同宗分库／独立实例 | 同一套 app 代码，货航独立库或独立部署 | **硬隔离时首选** |
| C 镜像分叉货航版 | 库＋代码长期双轨 | 贵、易漂；仅强合规且拒跟版时 |
| D 重开新系统新库 | 抛开天健模型重做 | 与已有十四级模块／公司码重复；默认否 |

### 7.2 建议口径（可对外说）

1. 天健已是货航可登录的飞行能力中台；问题是 **开通范围与数据隔离强度**，不是「有没有系统」。  
2. 功能裁剪：按 `frontResourceAll` 减配（学员、主业转升、客运相关等）——桌面黄标菜单可继续对照。  
3. 隔离：责任／审计要求高 → **B 分库或独立实例**；仅防误操作 → **A** 也可能够。  
4. 不要默认 C／D。

### 7.3 向项目组还要的硬材料（补齐「库表级彻底」）

1. 各 `*-app` 库名／schema 清单与是否已共库。  
2. 行级权限是否按 `hrBase`／`company`／`orgunitBase` 强制拦截。  
3. 若分库：人员主数据共享只读还是全量复制；与 IEB／排班／翔翼边界。  
4. 货航目标：跟南航同版本发布，还是允许滞后分支。

无以上四条，**应用与权限面已经明了**；**物理表结构**仍只能项目组给。
